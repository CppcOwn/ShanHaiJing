一、项目核心定位与架构原则
项目核心目标是构建一套纯无服务器架构的中国自然奇观文旅地球仪系统，以微信小程序为核心载体，为用户提供一站式自然奇观观测信息查询服务。核心服务人群包括热爱自然奇观观测的旅游爱好者、摄影爱好者和普通游客。

核心架构原则：
1. 前端完全无服务器：仅做静态展示与数据拉取，无任何实时 API 请求交互
2. 后端仅通过 Serverless 定时任务生成数据：使用云函数实现定时任务，负责生成全量数据文件
3. 数据存储与分发：将生成的数据推送到云存储，通过 CDN 加速分发
4. 前端数据拉取：直接从 CDN 拉取静态数据文件，实现轻量化运行

纯无服务器架构的优势：
- 服务器资源占用趋近于零，降低运维成本
- 系统弹性高，无需担心并发压力
- 前端轻量化，提升用户体验
- 弱网环境下依然可用

二、大屏展示系统设计
大屏展示系统以炫酷 3D 中国地图/地球仪为核心可视化载体，突出自然奇观观测点位的展示。

核心展示优先级：自然奇观观测点位 > 景区信息

界面布局：
- 中央区域：3D 地球仪/中国地图，标注自然奇观观测点位
- 左侧：自然奇观分类导航（云海、日出、星空、江潮、日照金山）
- 右侧：选中点位的详细信息展示
- 底部：时间轴和数据更新状态

全量展示内容：
- 自然奇观观测点位分布
- 观测条件预报
- 出现概率
- 最佳观测时段
- 机位实拍实况
- 周边配套信息
- 景区基础信息

自然奇观专属可视化效果：
- 不同类型奇观使用不同颜色标记
- 概率值通过热力图展示
- 最佳观测时段通过时间轴可视化
- 实拍实况轮播展示

数据更新机制：
- 大屏端通过定时拉取 CDN 上的静态数据文件更新
- 每 30 分钟拉取一次数据版本清单
- 对比本地版本判断是否需要更新具体数据文件

三、多端支持适配方案
微信小程序为核心优先级，其他端为配套适配。

核心功能一致性保障：
- 各端均提供自然奇观查询、预报功能
- 数据来源统一，均从 CDN 拉取静态文件
- 核心数据结构保持一致

各端差异化适配策略：
- 微信小程序：优先优化体验，确保轻量化和流畅运行
- 鸿蒙、iOS、安卓：原生应用适配，充分利用平台特性
- PC 端：提供更丰富的可视化效果和交互体验

各端实现逻辑：
- 微信小程序：使用小程序框架，实现 3D 可视化，通过 wx.request 拉取 CDN 静态文件
- 鸿蒙、iOS、安卓：使用各自平台的开发框架，实现本地缓存和增量更新
- PC 端：使用 Web 技术栈，实现更复杂的 3D 可视化效果

CDN 数据拉取策略：
- 启动时拉取数据版本清单
- 定时（每 30 分钟）检查版本更新
- 仅在版本变化时拉取具体数据文件
- 实现本地缓存，减少重复拉取

四、数据策略与无服务器实现专项

1. 静态数据（景区/观测点位基础信息、官网、票价、固定观测规则等）
- Serverless 定时触发规则：每日凌晨全量更新，增量更新通过手动触发
- 数据处理逻辑：从数据源获取基础信息，整理成结构化 JSON 格式
- 静态文件生成：生成 `static_data.json` 文件，包含所有静态信息
- 云存储推送：推送到云对象存储的 `static` 目录
- CDN 分发：配置 CDN 缓存时间为 24 小时
- 文件命名规则：`static_data_{timestamp}.json`

2. 通用天气数据（含实时天气、衣物推荐等）
- Serverless 定时触发规则：每 25 分钟触发一次
- 数据处理逻辑：调用第三方天气 API，处理数据后生成覆盖所有观测点位/景区的天气数据
- 静态文件生成：生成 `weather_data.json` 文件
- 云存储推送：推送到云对象存储的 `weather` 目录
- CDN 分发：配置 CDN 缓存时间为 25 分钟
- 文件命名规则：`weather_data_{timestamp}.json`
- 版本控制：通过 timestamp 判断版本是否更新

3. 自然奇观预报数据（云海/日出/星空/江潮/日照金山概率、最佳观测时段等）
- Serverless 定时触发规则：
  - 星空/日出：每日更新（凌晨 2 点）
  - 云海/江潮：每 4 小时更新
- 数据处理逻辑：基于天气数据和地理信息，预计算奇观出现概率和最佳观测时段
- 静态文件生成：生成 `wonder_forecast.json` 文件，按奇观类型分类
- 云存储推送：推送到云对象存储的 `forecast` 目录
- CDN 分发：配置 CDN 缓存时间根据奇观类型调整
- 文件命名规则：`wonder_forecast_{type}_{timestamp}.json`

五、极致资源优化策略

前端数据拉取优化：
- 预加载：启动时预加载核心数据文件
- 懒加载：非核心数据按需加载
- 增量更新：通过版本对比，仅更新变化的数据
- 本地缓存：将数据缓存到本地，减少重复拉取

CDN 缓存规则优化：
- 静态数据：24 小时缓存
- 天气数据：25 分钟缓存
- 自然奇观预报数据：根据更新频率设置缓存时间
- 数据版本清单：5 分钟缓存

文件压缩策略：
- 使用 gzip 压缩 JSON 文件
- 图片资源优化，使用 WebP 格式
- 代码压缩和混淆

弱网环境优化：
- 数据文件分块加载
- 降级策略：弱网时使用低分辨率资源
- 离线模式：使用本地缓存数据

六、技术架构设计（纯无服务器专项）

数据流转全链路：
1. Serverless 云函数定时触发
2. 云函数调用第三方 API 获取数据
3. 云函数处理数据并生成静态 JSON 文件
4. 云函数将文件推送到云对象存储
5. CDN 从云对象存储拉取文件并缓存
6. 前端从 CDN 拉取静态数据文件
7. 前端处理数据并展示

技术选型：
- Serverless 云函数：腾讯云云函数（与微信小程序集成更紧密）
- 云对象存储：腾讯云 COS
- CDN：腾讯云 CDN
- 前端 3D 可视化：Three.js（微信小程序适配版）
- 第三方天气 API：和风天气 API

配置规则：
- 云函数：设置定时触发器，配置环境变量存储 API 密钥
- 云对象存储：配置存储桶权限，设置跨域访问
- CDN：配置缓存规则，开启压缩
- 前端：配置 CDN 域名，实现数据拉取和更新逻辑

完全规避传统服务器与实时 API，实现纯无服务器架构，确保系统轻量化、高性能运行。
